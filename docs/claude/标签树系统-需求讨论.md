## 已确认的非技术需求

### 配置文件位置

所有标签配置放在 `.uvnote/tags/` 子文件夹下。

### 切换方式

文件树 / 标签树的切换开关在**活动栏（ActivityBar）**。

### UI 细节

- 标签节点：不需要额外图标，只有展开箭头 + 标签名
- 文件节点：保留文件图标 + 文件名
- 初始默认全部折叠
- 切换文件/标签视图时不重置折叠状态（会话内保持）

### 右键菜单

- 右键标签节点 → 排序选项
- 右键文件节点 → 跟文件树一样的行为

## 待实现

等你写完基础原理后，我根据你的描述来实现。

重要的前提概念：
1. 每个文件都有其特征，我称之为标签，每个文件都有很多标签，可能重复
2. 标签之间不一定是父子关系和平级关系，就像现实世界特征不可能只有父子关系和平级关系。这是最重要的概念，比方说"开发日志"里面有四个功能的子文件夹，但同时我也可以说"四个功能"有子文件夹"开发日志"和"使用简介"。
3. 因为系统管理只支持层级管理，我这种结构必须要存储额外的信息，所以每个文件需要有自己的ID，即使重命名或者移动位置，方便定位。用文件的创建时间戳（birthtimeMs）生成唯一 FileID，因为重命名和移动都不会改变创建时间。Node.js 无法直接获取 Windows NTFS 底层文件 ID，所以用时间戳方案替代
4. 文件所拥有的标签分为三类：其所在路径所决定的标签，文件内部手写的标签，其他

如何实现
1. 用一个文件记录每个文件所拥有的标签，所在路径决定的标签单拎出来
2. 用一个文件决定如何显示这个标签树，决定这个结构，在初始状态结构由系统文件管理器的层级结构决定，且每个文件由路径决定的标签在这个时候修改，每次刷新都是重新修改这两部分
3. 接下来是一个便利操作，再使用一个文件夹把存储标签树的文件翻译成人容易看懂的模式，用缩进代替父子关系，同时非常重要的是，我可以通过修改该文件修改标签树文件
4. 刷新方式：刷新按钮除了第一次更换工作区应该不用再按，其他时候，注意三个部分，系统文件管理器的层级结构有没有变，存储标签树的文件有没有变，便利操作的文件有没有变。这三个地方哪个变了都要更新两个文件
5. 标签式管理器的显示原则：根据标签树文件渲染出对应的和文件夹列表类似的列表，在每个文件夹下。找满足该标签文件夹名字及其父标签文件夹名字（其上的每一个顶层都要满足），且该文件夹下的子标签夹的名字都不满足，就显示在当前标签夹。所有标签都不满足就显示在所有标签夹下面，这一步计算量大，可以用空间换时间，可以用一个cache放tag文件夹下面，你来决定
6. 用户可以在文件编辑类似"#标签"，这时候就更新记录文件所拥有标签的文件
7. 每个文件都有一个默认的"#重要程度:0"标签，且用户在文件里面编辑时若也用了标签加冒号（中英文都可以），就更新在记录文件所拥有标签的文件。
8. 右键标签夹，可以弹窗选择用什么排序方式，包括用重要程度的标签后面的数字大小
9. 顶部是工作区文件夹名称，加粗显示
10. 在活动栏显示一个图标与文件列表切换
