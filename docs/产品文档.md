## 一、产品定位

UV Note 是一款 **Windows 桌面端本地笔记软件**，灵感来源于 Obsidian。核心理念：

- **数据完全归你所有** — 所有笔记以普通文件（Markdown）存储在你的电脑上
- **文件夹即工作区** — 选择一个文件夹，里面的一切就是你的笔记库
- **自由排序** — 文件和文件夹可以像卡片一样自由拖拽排列，不受时间排序限制
- **可扩展** — 后续逐步加入提醒、精炼、可视化等功能

---

## 二、核心功能

### 2.1 工作区管理

- 选择一个本地文件夹作为"工作区"（笔记库）
- 软件读取该文件夹内的所有 Markdown 文件（`.md`）和子文件夹
- 以文件树 + 可视化的形式展示在侧边栏
- 支持切换不同工作区

### 2.2 自由排序

用户可以在侧边栏中**自由拖动文件和文件夹**来改变它们的排列顺序。

#### 排序的实现原理（待用户选择方案）

**你的思路（推荐 ✅）：配置文件记录位置**

在文件夹根目录放一个隐藏配置文件（如 `.uvnote/order.json`），里面记录每个文件和文件夹的排序位置。软件渲染时按这个文件里的顺序显示，而不是按文件创建时间。

```
工作区/
├── .uvnote/
│   └── order.json          ← 记录排序的配置文件
├── 笔记A.md                ← order.json 里记录排第1
├── 笔记B.md                ← order.json 里记录排第2
└── 学习/                   ← order.json 里记录排第3
    └── ...
```

**order.json 内容示例：**
```json
{
  "": ["笔记A.md", "笔记B.md", "学习"],
  "学习": ["第1课.md", "第2课.md", "复习.md"]
}
```

- `""` 表示根目录下的排序
- `"学习"` 表示"学习"文件夹内部的排序
- 每个数组里的顺序就是显示顺序
- 新文件自动追加到末尾

**优点：**
- 简单透明，你可以直接打开 JSON 文件查看和手动修改
- 不会污染笔记文件本身
- 即使软件卸载，排序信息还在文件夹里
- 可以把这个配置文件放到 git 里，同步到其他电脑

**缺点：**
- 文件很多（比如上千个）时，配置文件会变得很大
- 如果手动改错了 JSON 格式，软件启动可能报错（需要做容错处理）

---

**备选方案 B：SQLite 数据库**

在 `.uvnote/` 目录下放一个小型数据库文件，用数据库来记录排序。

**优点：**
- 处理大量文件（上万个）时性能更好
- 数据操作更安全，不容易损坏

**缺点：**
- 数据库文件是二进制格式，你无法直接打开查看/手动修改
- 多了一层技术复杂度
- 对于笔记软件来说，"杀鸡用牛刀"

---

**对比总结：**

| 维度 | 方案 A：JSON 配置文件 | 方案 B：SQLite 数据库 |
|------|----------------------|----------------------|
| 可读性 | ✅ 可直接打开看 | ❌ 二进制，看不懂 |
| 手动修改 | ✅ 可以 | ❌ 不行 |
| 大量文件性能 | ⚠️ 一般（千级够用） | ✅ 好 |
| 实现复杂度 | ✅ 简单 | ⚠️ 复杂 |
| git 同步 | ✅ 文本文件很好同步 | ⚠️ 二进制不好 diff |

**我的推荐：方案 A（JSON 配置文件）**，因为笔记软件通常不会一个文件夹里有上万个文件，JSON 完全够用。

---

### 2.3 防误操作：Alt 键 + 拖动

为了避免平时点击时不小心触发了拖动，采用**按住 Alt 键才能拖动**的设计：

- 普通点击：选中文件（高亮）
- **按住 Alt + 鼠标拖动**：移动文件/文件夹的排序位置
- 拖动时显示一条插入线，指示将要放到的位置
- 松开鼠标：文件移动到新位置，配置文件自动更新

备选讨论：也可以考虑"长按拖动"（按住 0.5 秒后才能拖动），但 Alt 键方案更精确、响应更快。

## 三、技术方案（待用户决定）

作为一个桌面应用，我们需要选择一个"容器"来承载 React 写的界面，同时让它能访问你电脑的文件系统。

### 方案 1：Electron

**是什么：** Electron 就像一个"自带浏览器的壳"，把你的 React 网页包在里面变成一个桌面程序。VS Code、Obsidian、Notion 桌面版都是用这个。

**优点：**
- 生态最成熟，插件/教程最多，遇到问题容易搜到答案
- 文件系统访问很方便
- Obsidian 也是用这个，说明笔记类软件完全够用
- 社区庞大，长期维护有保障

**缺点：**
- 打包后的安装包比较大（约 80MB~150MB），因为把一整个 Chromium 浏览器打包进去了
- 内存占用相对较高（启动约 100MB~200MB）
- 启动速度中等（通常 2~4 秒）

---

### 方案 2：Tauri

**是什么：** Tauri 是新一代的桌面框架，它利用 Windows 自带的 WebView（Edge 内核），不需要打包一整个浏览器。安装包可以很小。

**优点：**
- 安装包很小（约 5MB~20MB）
- 内存占用低（启动约 30MB~80MB）
- 启动速度快
- 安全性更好

**缺点：**
- 生态较新，教程和社区资源比 Electron 少
- 某些 Windows 旧版本（Win7/Win8）的 WebView 可能需要额外安装
- 遇到冷门问题时可能不好找答案
- 使用 Rust 语言作为后端（如果需要自定义后端逻辑，学习成本高）

---

**对比总结：**

| 维度 | Electron | Tauri |
|------|----------|-------|
| 安装包大小 | 80~150MB | 5~20MB |
| 内存占用 | 100~200MB | 30~80MB |
| 启动速度 | 2~4秒 | 1~2秒 |
| 生态/教程 | ✅ 非常丰富 | ⚠️ 还在成长 |
| 遇到问题好解决 | ✅ | ⚠️ 相对难 |
| Windows 兼容性 | ✅ Win10/11 完美 | ⚠️ 需要较新 WebView |
| Obsidian 同类参考 | ✅ 很多 | ⚠️ 较少 |

**我的推荐：Electron**，原因很简单——你是新手，Electron 资料最多，踩坑最少。而且你的目标平台是 Win11，兼容性没问题。安装包大小对于笔记软件来说不是核心问题。

## 四、UI 布局设计

参考 Obsidian 的经典布局，初版采用三栏结构：

```
┌──────────┬──────────────────┬──────────┐
│          │                  │          │
│  侧边栏  │    编辑区域      │  大纲/   │
│  (文件树) │   (Markdown     │  属性面板 │
│          │    编辑器)       │          │
│  - 文件夹 │                  │  - 标题大纲│
│  - 文件  │  可打开多个      │  - 标签   │
│  - 拖拽  │  标签页          │  - 链接   │
│  排序    │                  │          │
│          │                  │          │
└──────────┴──────────────────┴──────────┘
```

- **左侧栏：** 文件树 + 自由拖拽排序
- **中间：** Markdown 编辑器（支持多标签页）
- **右侧栏：** 大纲/属性面板（可选，初版可先不做）

## 五、文件存储约定

```
我的笔记工作区/              ← 用户选择的文件夹
├── .uvnote/                ← 软件配置目录（隐藏）
│   ├── order.json           ← 文件排序配置
│   ├── workspace.json       ← 工作区设置
│   └── ...
├── 01-学习笔记/             ← 用户文件夹
│   ├── 英语.md
│   └── 数学.md
├── 02-工作/                 ← 用户文件夹
│   └── 项目A.md
├── 阅读清单.md              ← 用户文件
└── 每日记录.md              ← 用户文件
```

- 所有配置放在 `.uvnote/` 隐藏目录中
- 用户数据就是普通的 `.md` 文件和文件夹，不做任何修改
- 即使不用 UV Note，用其他编辑器也能正常打开这些笔记
